# Development guide

## Prerequisites and configuration

Derive versions and tools from the repository. Document configuration names and
where runtime secrets come from without including their values.

## Install, run and check

| Purpose | Actual command or wrapper | Expected result | Evidence/status |
| --- | --- | --- | --- |
| Install/run/check | Command supported by the scaffold | Observable success | Run result, unverified or planned |

For a docs-only project, explain which commands do not exist yet. Respect the
repository's test policy and use its existing verification approach.

## Contribution workflow

Explain branch, code style, review and PR conventions that apply. Point to their
authoritative files rather than duplicating them.

## Troubleshooting

Include observed failures and fixes when available. Mark hypothetical operations
as planned; no invented successful installation or verification.
