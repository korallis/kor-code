# User guide

## Availability and access

Say which tasks work now and which are planned. Explain user roles and required
access using glossary terms.

## Primary task

Give the starting state, numbered user actions and visible success result.
For each additional task, repeat this shape only where it adds useful guidance.

## Screens and recovery

For working UI, include inspected captures of the real app with captions and
relative image links. Before implementation, state screenshots are pending;
mockups, if linked, are designs. For non-UI tools, show real command output when
available. Describe expected errors, access limits and recovery without claiming
unobserved behaviour has been verified.

## Limits and help

Explain relevant constraints and known gaps. Connect unresolved behaviour to an
owned open question instead of guessing the answer.
