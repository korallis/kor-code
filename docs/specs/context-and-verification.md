# Context and verification specification

**Status: Validated for worktree-only discovery, bounded redaction/compaction, Jev fixture ranking, per-execution evidence gates, configured check execution, diff collection, and bounded repair on fake Linear. GitHub review/check integration remains Proposed.**

## Context boundary

Repository rules are discovered after resolving the execution worktree. Discovery recursively reads only repository-owned `AGENTS.md`, `CLAUDE.md`, `CLAUDE.local.md`, `CONTRIBUTING.md`, `INSTRUCTIONS.md`, and Markdown files under `.claude/rules/`; `.git` and `node_modules` are skipped. A resolved path must remain inside the worktree. The discovery code never reads user homes, Claude or Codex configuration, agent directories, or CLIProxyAPI files.

Context sources carry a stable identifier, relative path, purpose, and Jev relevance score. Jev receives bounded redacted excerpts; a caller rank callback is an explicit recorded override. The manifest records the execution, repository, worktree, selected sources, dropped source references, compaction, and redaction state. Compaction truncates sources to a bounded character budget while preserving source order. All text, including the issue sent to Jev, passes through the existing `@kor-code/jev` `redact` function.

## Verification boundary

`VerificationTracker` stores evidence for one execution and maps it to acceptance conditions through `acceptanceId`. A required condition is passing only when at least one linked evidence item has `status: pass`; missing, unresolved, or failing evidence cannot complete an execution. `assertComplete()` raises `VerificationError` with the condition findings, and the controller records that block before releasing the lease for an explicit retry. Each configured repository check is run in the execution worktree; its exit code is authoritative. Kor collects the diff and asks Jev one Noul per criterion using the configured threshold, then retries with the failed check and criterion findings at most twice. A final failure records every criterion finding in Linear and cannot transition to complete. Review evidence uses the same core evidence contract, but no GitHub review/check adapter is implemented yet.

When a Linear runtime is configured, the controller creates a fresh tracker from `execution.manifest.acceptance` for every dispatch. A session is followed by each configured repository check in the worktree; the process exit code is authoritative. Kor captures the diff and asks Jev one Noul per criterion over the check output and diff, using the configured threshold. A blocked attempt is retried with its exact findings at most twice. The latest attempt must have a successful session, passing checks, and passing findings before `AgentSessionWriter.complete`; otherwise every criterion finding is written to Linear, the issue remains running, the lease is released, and a verification error is raised. Invalid or cross-execution evidence is recorded as a verification block as well. Runs without a Linear writer still raise on a configured verification failure, so an unmet criterion never appears complete.
